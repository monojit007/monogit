# 12. Word-by-word Glossary

Use this file as a dictionary. The chapters tell the story. This list gives each important word a short, plain meaning. Words are grouped in the same order as the syllabus so you can revise one topic at a time.

---

## Front-end technologies

| Word | Meaning |
| --- | --- |
| Front end | The part of an application the user sees and operates |
| Client side | Work that happens on the user's device |
| Browser | The program that opens web pages, such as Chrome, Edge, Firefox, or Safari |
| Web page | One document the browser displays |
| Website | A set of related web pages |
| Web application | A website that does a job for the user, such as showing a balance or taking a transfer |
| HTML | HyperText Markup Language. The language that describes the structure of a page |
| HyperText | Text that can link to other text or pages |
| Markup | Labels around content that say what each piece is |
| HTML5 | The modern version of HTML |
| DOCTYPE | The first line that tells the browser which HTML rules to use |
| Tag | A marker in angle brackets, such as `<p>` |
| Opening tag | The start marker, such as `<p>` |
| Closing tag | The end marker, such as `</p>` |
| Element | The opening tag, the content, and the closing tag together |
| Attribute | Extra information inside a tag, such as `href` or `type` |
| Head | The part of the page that holds the title and links, usually not shown as the main content |
| Body | The part of the page the user sees |
| Title | The name on the browser tab |
| Heading | A title line. `h1` is the most important, then `h2` downward |
| Paragraph | A normal block of text, marked with `p` |
| Anchor | The `a` element, used for a link |
| href | The address a link points to |
| Image | A picture. The `img` tag places it |
| src | The source address of a file, such as an image |
| alt | Alternative text for an image, used when the image cannot be seen |
| Unordered list | A bullet list, `ul` |
| Ordered list | A numbered list, `ol` |
| List item | One entry in a list, `li` |
| Table | Rows and columns of data |
| Table row | One horizontal line in a table, `tr` |
| Header cell | A column or row title in a table, `th` |
| Data cell | An ordinary table cell, `td` |
| Form | A group of fields the user fills and submits |
| Label | The words that say what a field means |
| Input | A field the user can type in or choose |
| Placeholder | Hint text shown inside an empty field |
| Required | A rule that the field cannot be submitted empty |
| Checkbox | A box that can be ticked or unticked |
| Radio button | A round choice where one option in a group is selected |
| Drop-down | A list that opens so the user can pick one option |
| Text area | A large box for many lines of text |
| Submit | Send the form |
| Hidden field | A value sent with the form that the user does not see. Not a place for a real secret |
| Button | Something the user clicks to take an action |
| Semantic HTML | Tags whose names describe meaning, such as `header`, `nav`, `main`, and `footer` |
| div | A plain box with no special meaning |
| Header | The top region of a page or section |
| Navigation | The set of links used to move around |
| Main | The primary content of the page |
| Section | A grouped part of a page |
| Article | A self-contained piece of content |
| Aside | Side content |
| Footer | The bottom region of a page |
| Accessibility | Design that people with disabilities can use |
| Screen reader | Software that reads a page aloud |
| CSS | Cascading Style Sheets. The language that controls look and layout |
| Style sheet | A file or block of CSS rules |
| Cascading | The ordered way the browser decides which rule wins |
| Selector | The part of a CSS rule that chooses which elements to style |
| Property | The thing being styled, such as colour or size |
| Value | The setting given to a property |
| Rule | One complete CSS instruction |
| Class | A reusable name for styling one or many elements |
| ID | A name that should belong to only one element on the page |
| Specificity | How strongly a selector targets an element. An id is stronger than a class |
| Inheritance | Some styles pass from a parent element to its children |
| Box model | The four layers of an element: content, padding, border, and margin |
| Content | The words or picture inside the box |
| Padding | Space inside the border, around the content |
| Border | The line around the padding |
| Margin | Space outside the border, between boxes |
| Display | How an element participates in layout |
| Flexbox | A layout method for a row or a column |
| Grid | A layout method for rows and columns together |
| Position | A way to place an element, including relative, absolute, fixed, and sticky |
| Responsive design | A page that rearranges itself to fit different screen sizes |
| Viewport | The visible area of the screen |
| Media query | A CSS rule that applies only when a screen condition is true |
| Mobile first | Designing the small screen first, then adding rules for larger screens |
| Relative unit | A size that scales, such as percent, em, or rem |
| Inline style | CSS written inside an HTML tag. Hard to reuse |
| Internal style | CSS written in a style block on one page |
| External style sheet | A separate CSS file shared by many pages |
| Cache, for CSS | The browser stores the file so the next visit need not download it again |
| JavaScript | The programming language that runs in the browser and makes pages interactive |
| Script | A JavaScript program |
| Variable | A named place that holds a value |
| Constant | A value the program should not reassign |
| String | Text data |
| Number | Numeric data |
| Boolean | A true or false value |
| Array | An ordered list of values |
| Object | A group of named values |
| Null | A deliberate empty value |
| Undefined | A value that has not been given |
| Operator | A symbol that acts on values, such as plus or compare |
| Condition | A decision, such as if and else |
| Loop | A repeat |
| Function | A named packet of steps |
| Return | The value a function sends back |
| DOM | Document Object Model. The browser's live tree of the page |
| document | The JavaScript object that represents the page |
| Event | Something that happens, such as a click or a key press |
| Event listener | Code that waits for an event and then runs |
| AJAX | A way for JavaScript to ask the server for data without reloading the whole page |
| Asynchronous | Work that starts and finishes later, without freezing the page |
| fetch | The modern JavaScript function for sending a request |
| Promise | JavaScript's way of handling a result that will arrive later |
| JSON | JavaScript Object Notation. A light text format for data |
| XML | A stricter, more verbose text format still used in some bank interfaces |
| Client-side validation | Checks done in the browser. Helpful, and not sufficient |
| Cookie | A small piece of data the browser stores for a site |
| localStorage | Browser storage that remains until deleted |
| sessionStorage | Browser storage that lasts until the tab closes |
| ES6 | A modern generation of JavaScript |
| ECMAScript | The official standard name of JavaScript |
| Module | A JavaScript file that shares some of its functions with other files |
| Node.js | JavaScript running on a server, outside the browser |
| UI | User interface. The screens and controls a person uses |
| UX | User experience. How easy and clear the whole journey feels |
| Framework | A prepared structure you build inside |
| Library | A toolbox you call when you need it |
| Component | A reusable piece of a screen, with its own data and look |
| Props | Inputs passed into a component |
| State | Data that can change and should update the screen |
| Rendering | Turning a description of the screen into what the user sees |
| Binding | A connection that keeps data and the screen in step |
| SPA | Single Page Application. One page shell, with views changed by JavaScript |
| Multi-page application | Each screen is a separate page loaded from the server |
| Routing | Choosing which screen to show for an address |
| JSX | A way of writing HTML-like markup inside React code |
| Virtual DOM | A lightweight copy React uses to calculate the smallest screen update |
| React | A popular component-based UI library |
| Angular | A full UI framework, commonly written in TypeScript |
| AngularJS | The older generation of Angular. Not the same as modern Angular |
| Vue | A progressive UI framework known for a gentler start |
| TypeScript | JavaScript with declared types that catch mistakes earlier |
| Build tool | Software that packs source files into files the browser can load |
| Package manager | A tool, such as npm, that downloads libraries |
| Design system | An organisation's shared colours, type, and components |
| Bootstrap | A CSS framework of ready-made layout and form styles |
| Tailwind | A styling approach that uses many small utility classes |
| Material Design | A visual guideline. Not itself the application framework |

## Back-end and server-side processing

| Word | Meaning |
| --- | --- |
| Back end | The server-side programs, rules, and data access |
| Server | A computer, or a program, that waits for requests and sends responses |
| Server side | Work done on the server |
| Client | The device or program that asks |
| Request | The message sent by the client |
| Response | The message sent back by the server |
| Server-side processing | Everything the server does between receiving a request and sending a response |
| Web server | Software that accepts HTTP and can serve files or forward requests. Nginx, Apache, and IIS are examples |
| Application server | Software that runs the bank's own logic. Tomcat, JBoss, WebLogic, and WebSphere are examples |
| Reverse proxy | A server that accepts client traffic and forwards it inward |
| Java | A widely used language for large bank systems |
| JVM | Java Virtual Machine. The runtime that executes Java programs |
| Spring | A popular Java framework for building services |
| Jakarta EE | The enterprise Java platform |
| Servlet | A Java class that handles an HTTP request |
| JSP | JavaServer Pages. HTML with Java, used to build pages on the server |
| Python | A language used for web services, automation, and data work |
| PHP | A language used by many traditional websites |
| C# and ASP.NET | Microsoft's common back-end path |
| ORM | Object-relational mapping. A tool that saves program objects as database rows |
| Hibernate | A well-known Java ORM |
| Static content | Content that is the same for every user, such as a logo |
| Dynamic content | Content built for the user and the moment, such as a balance |
| Server-side rendering | The server builds the HTML |
| Client-side rendering | The browser builds the screen from data |
| Template | A page shape with blanks the server fills |
| Stateless | Each request stands alone. HTTP is stateless |
| State | Remembered information, such as who is logged in |
| Session | Server-side memory of a logged-in user, found by a session id |
| Session id | A long random value that points to a session. It is not the user id |
| Token | A credential presented with a request, often after login |
| Middleware | Software in the middle that does a shared job such as security, logging, or messaging |
| Message queue | A holding line for messages until another program can process them |
| Kafka | A distributed platform for streams of events |
| RabbitMQ | A popular message-queue product |
| IBM MQ | A message system long used in enterprises |
| MVC | Model, View, Controller. A way to separate data and rules, presentation, and request handling |
| Model | The data and the business rules |
| View | What is shown, or the response that will be shown |
| Controller | The part that receives a request and calls the model |
| Service layer | The part of the code that applies business rules |
| Repository | The part of the code that reads and writes storage |
| Database | An organised store of data |
| Relational database | Data in related tables. Oracle, PostgreSQL, MySQL, SQL Server, and DB2 are examples |
| Table | A set of rows about one subject |
| Row | One record |
| Column | One field |
| Primary key | The value that uniquely identifies a row |
| Foreign key | A value that points to a row in another table |
| SQL | Structured Query Language. The language for relational data |
| SELECT | Read data |
| INSERT | Add data |
| UPDATE | Change data |
| DELETE | Remove data |
| Database transaction | A group of steps that commit together or roll back together |
| Commit | Make the transaction permanent |
| Rollback | Undo the current uncommitted transaction |
| ACID | Atomicity, consistency, isolation, durability |
| Atomicity | All steps succeed, or none do |
| Consistency | Data moves from one valid state to another valid state |
| Isolation | Concurrent transactions do not see each other's half-finished work |
| Durability | Committed data survives a crash |
| Index | A lookup aid that speeds a search |
| NoSQL | A database that is not a classic relational design |
| Connection pool | A set of ready database connections that programs borrow and return |
| Authentication | Proving who you are |
| Authorisation | Deciding what you are allowed to do |
| SSO | Single sign-on. One login for several allowed applications |
| MFA | Multi-factor authentication. More than one kind of proof |
| 2FA | Two-factor authentication |
| OTP | One-time password. Valid briefly and usually once |
| Factor | A kind of proof: something you know, have, or are |
| Business rule | A bank decision such as a limit, a cutoff, or an entitlement |
| Application log | A technical record used to diagnose failures |
| Audit log | A record of who did what, to what, and when |
| Idempotency | Repeating the same intended operation does not repeat its effect |
| Idempotency key | A unique id that lets the server recognise a retry |
| Core banking | The system of record for the bank's ledger and main products |
| Channel | A way the customer or staff reaches the bank, such as mobile, branch, or ATM |
| System of record | The official place a fact is kept |

## Web architecture

| Word | Meaning |
| --- | --- |
| Architecture | The plan of parts and how they communicate |
| Client-server | One side asks, the other side serves, and the data stays central |
| Thin client | A client that mostly displays and collects input |
| Thick client | A client that contains a lot of logic |
| DNS | The directory that turns a site name into a numeric address |
| HTTP | The protocol of web requests and responses |
| Layer | A logical separation, such as presentation, rules, and data |
| Tier | A physical separation onto different machines or groups |
| 1-tier | Screen, rules, and data in one place |
| 2-tier | Usually a client talking directly to a database |
| 3-tier | Presentation tier, application tier, and data tier |
| Presentation tier | The user interface |
| Application tier | The business logic |
| Data tier | The database |
| N-tier | More than three separated tiers |
| Monolith | One deployable application that contains many functions |
| Microservice | A small service that owns one business capability and can be deployed on its own |
| Loose coupling | Services depend on contracts, not on each other's private insides |
| Bounded context | The clear edge of what one service owns |
| API contract | The agreed shape of requests and responses |
| Service discovery | How services find each other's current address |
| Orchestration | A coordinator directs the steps |
| Choreography | Services react to events without one conductor |
| Synchronous | The caller waits for the answer |
| Asynchronous | The caller does not wait for the whole downstream job |
| Fault isolation | A failure in one part does not have to sink the others |
| Observability | Logs, metrics, and traces |
| Distributed tracing | Following one request across many services with a shared id |
| SOA | Service-oriented architecture. Building the enterprise from reusable services |
| ESB | Enterprise service bus. A central integration and transformation layer |
| Load balancer | A component that spreads requests across healthy copies |
| Cache | A nearby copy of data that is expensive to recompute |
| High availability | The service continues despite failures |
| Failover | A standby takes over from a failed part |
| Redundancy | Extra copies of a critical part, on purpose |
| Vertical scaling | A bigger machine |
| Horizontal scaling | More machines |
| Network zone | A separated part of the network with its own access rules |
| DMZ | A buffer zone between the internet and the inner network |
| Firewall | A rule-based control that allows or blocks traffic |
| Scalability | The ability to handle growth by adding resources |

## Web security

| Word | Meaning |
| --- | --- |
| Confidentiality | Unauthorised people cannot read the data |
| Integrity | Data cannot be changed without detection |
| Availability | Legitimate users can use the service |
| Authenticity | The other party is genuine |
| Non-repudiation | An actor cannot convincingly deny what they did |
| Accountability | Actions can be traced to a person or process |
| CIA | Confidentiality, integrity, and availability |
| OWASP | Open Worldwide Application Security Project. A community that publishes web security guidance |
| OWASP Top 10 | Its list of the most critical web application security risks |
| Broken access control | Missing or weak enforcement of what a user may do |
| Deny by default | Start with no permission and grant only what is needed |
| Cryptographic failure | Weak or missing protection of sensitive data |
| Hash, for passwords | A one-way transformation. The password is not stored in plain text |
| Salt | Extra random data mixed into a password hash so identical passwords do not look identical |
| bcrypt, scrypt, Argon2 | Slow hash methods suitable for passwords |
| Injection | Untrusted input is treated as a command |
| SQL injection | Input changes the meaning of a database query |
| Parameterised query | The query shape is fixed and the input is passed as data. Also called a prepared statement |
| Least privilege | Only the access that is needed |
| Insecure design | A weakness in the design itself, before coding |
| Threat modelling | Thinking, during design, about how a journey could be abused |
| Security misconfiguration | Unsafe settings, defaults, or exposed debug features |
| Vulnerable component | A library with a known flaw |
| Authentication failure | Weak login, weak session, or weak credential handling |
| Credential stuffing | Trying username and password pairs stolen from somewhere else |
| Session fixation | Tricking a user into logging in to a session id the attacker already knows |
| Session regeneration | Issuing a new session id at login |
| Integrity failure | Trusting code or data that was not verified |
| Deserialisation | Rebuilding a live object from stored bytes. Dangerous with untrusted input |
| Logging and monitoring failure | An attack or misuse happens and nobody can see it |
| SSRF | Server-side request forgery. The server is tricked into calling an internal address for the attacker |
| XSS | Cross-site scripting. An attacker’s script runs in a victim’s browser through your page |
| Output encoding | Writing user text so the browser shows it as text and not as code |
| Content Security Policy | A header that tells the browser which scripts and sources are allowed |
| CSRF | Cross-site request forgery. Another site triggers an action using the victim’s existing login |
| CSRF token | An unpredictable value the real page sends and a foreign page cannot read |
| Clickjacking | A transparent page tricks the user into clicking something else |
| Brute force | Trying many passwords |
| WAF | Web Application Firewall. A filter in front of the application |
| DDoS | Distributed denial of service. A flood of traffic meant to make a service unavailable |
| Rate limiting | A cap on how many attempts are allowed in a period |
| Security header | An instruction from the server to the browser that hardens behaviour |
| Penetration test | An authorised attempt by experts to find weaknesses |
| Vulnerability assessment | A scan for known weaknesses |
| Patch | A fix for a flaw |
| Incident response | The planned way to detect, contain, and recover from a security event |
| HTTP | HyperText Transfer Protocol |
| HTTPS | HTTP secured by TLS |
| TLS | Transport Layer Security. The protocol that secures the channel |
| SSL | The older, retired protocol that TLS replaced |
| Certificate | A signed document that binds a name to a public key |
| Public key | The key that can be shared |
| Private key | The matching secret key |
| Certificate Authority | An organisation that browsers trust to sign certificates |
| Certificate chain | The path from the site certificate up to a trusted root |
| Self-signed certificate | A certificate signed by its own creator. Not for the public |
| Handshake | The opening exchange in which TLS is set up |
| Cipher suite | The set of algorithms chosen for a TLS connection |
| TLS 1.3 | The modern TLS version |
| Forward secrecy | Past recorded sessions stay safe even if the long-term private key is later stolen |
| Revocation | Cancelling a certificate before it expires |
| HSTS | A header that tells the browser to use HTTPS only for this site |
| Mixed content | A secure page that also loads insecure content |
| Secure cookie flag | Send the cookie only on HTTPS |
| HttpOnly | JavaScript cannot read the cookie |
| SameSite | Limits when the browser sends the cookie from another site |
| Idle timeout | End the session after a quiet period |
| Absolute timeout | End the session after a maximum lifetime |
| JWT | JSON Web Token. A signed set of claims |
| Claim | A statement inside a token, such as the user id and the expiry |
| Defence in depth | Several layers of control, not one |
| Data minimisation | Collect and keep only what you need |
| DPDP Act | India's Digital Personal Data Protection Act, 2023. The broad privacy law |

## APIs and web services

| Word | Meaning |
| --- | --- |
| API | Application Programming Interface. A defined way for one program to use another |
| Interface | The agreed surface. Callers do not need the private internals |
| Web service | A service offered over a network using web standards |
| Endpoint | One addressable action or resource |
| Contract | The published inputs, outputs, and errors |
| Consumer | The caller |
| Provider | The service that answers |
| Version | A generation of an API, so old callers can keep working |
| Public API | An API exposed outside the organisation |
| Internal API | An API used only inside the organisation |
| Partner API | An API shared with a known outside party |
| HTTP method | The verb of a request: GET, POST, PUT, PATCH, DELETE, and others |
| GET | Read. It must not change data |
| POST | Create, or start an action |
| PUT | Replace a whole resource |
| PATCH | Change part of a resource |
| DELETE | Remove a resource |
| Idempotent method | A method that can be repeated without a further effect. GET, PUT, and DELETE are designed this way |
| Status code | The number that summarises the result |
| 200 | Success |
| 201 | Created |
| 202 | Accepted for later processing |
| 400 | The request is malformed |
| 401 | Identity was not proved |
| 403 | The caller is known and is not allowed |
| 404 | Not found |
| 409 | Conflict with the current state |
| 429 | Too many requests |
| 500 | An unexpected server failure |
| Header | Metadata sent with a request or response |
| REST | Representational State Transfer. A style based on resources and HTTP |
| Resource | A thing the API names, such as an account |
| URL | The address of a resource |
| Representation | The picture of a resource sent over the wire, such as JSON |
| Uniform interface | Standard methods and meanings used consistently |
| Cacheable | A response may declare that it can be reused |
| Layered system | The caller does not know every hop behind the door |
| HATEOAS | Responses include links that say what the client may do next |
| Richardson maturity model | A ladder from a single URL up toward full REST |
| OpenAPI | A popular way to describe a REST API. Associated with Swagger |
| Swagger | The earlier name and tooling around OpenAPI |
| SOAP | Simple Object Access Protocol. An XML message protocol |
| Envelope | The outer SOAP wrapper |
| SOAP header | Control information in the envelope |
| SOAP body | The business content |
| SOAP fault | A SOAP-shaped error |
| WSDL | Web Services Description Language. The XML contract of a SOAP service |
| XML Schema | The strict grammar of the XML data |
| UDDI | An old directory idea for finding web services |
| WS-Security | Standards for securing SOAP messages |
| API gateway | The front door that routes, checks, limits, and logs API calls |
| Routing | Sending a request to the correct service |
| Rate limit | A maximum number of calls |
| Throttling | Slowing a caller |
| Quota | An allowance over a period |
| TLS termination | Decrypting HTTPS at a chosen door |
| Transformation | Converting a request or response from one shape to another |
| Facade | A simpler front placed over a more complex system |
| Correlation id | An id passed along a call so the whole path can be traced |
| API key | A secret that identifies a calling application. Not a customer login |
| Client certificate | A certificate that identifies a calling system |
| OAuth 2.0 | A way to grant limited access without sharing the password |
| Scope | The exact permission granted, such as read accounts |
| Access token | The short-lived credential the client uses |
| Refresh token | A longer-lived credential used to obtain a new access token |
| OpenID Connect | An identity layer on top of OAuth, used for login |
| Resource owner | In OAuth, the user who grants access |
| Authorisation server | The component that issues tokens after the user approves |
| Resource server | The API that holds the protected data |
| HMAC | A signature made with a shared secret, used to detect tampering |
| mTLS | Mutual TLS. Both sides present certificates |
| Account Aggregator | An Indian consent-based framework for sharing financial information |
| Pagination | Returning results in pages |
| Backward compatibility | A change that does not break existing callers |
| Deprecation | A planned retirement of an old version |
| Webhook | The server calls the client later, when an event happens |
| BOLA | Broken object-level authorisation. An API fails to check that this caller may touch this specific record |
| Timeout | The maximum time to wait before giving up |

## Performance and scalability

| Word | Meaning |
| --- | --- |
| Performance | How fast and smoothly the system serves current demand |
| Latency | Waiting time for one request |
| Response time | The time from request to completed answer |
| Throughput | Work completed in a period |
| Concurrent users | Users in the middle of work at the same moment |
| Error rate | The share of requests that fail |
| Percentile | A point in the distribution. p95 means 95 percent of requests were at least this fast |
| Saturation | A resource is close to fully used |
| SLA | A promised service level |
| SLO | An internal service objective |
| SLI | A measured service indicator |
| Bottleneck | The narrowest part that limits the whole system |
| Profiling | Finding where time and resources are spent |
| Load testing | Simulating expected heavy use |
| Stress testing | Pushing beyond the peak to see how the system fails |
| Soak testing | Running a realistic load for a long time |
| Minification | Removing unnecessary characters from code sent to the browser |
| Compression | Packing bytes for transfer. Gzip and Brotli are common |
| Lazy loading | Loading something only when it is about to be needed |
| CDN | Content Delivery Network. Copies of content placed near users |
| Origin | The bank's own server that a CDN falls back to |
| TTL | Time to live. How long a cached or DNS value may be kept |
| Cache hit | The copy was found and used |
| Cache miss | The copy was absent, so the source was used |
| Invalidation | Removing a cached copy because the source changed |
| Cache stampede | Many requests rush to rebuild the same expired item |
| Redis | A fast in-memory data store, often used as a cache |
| Memcached | Another in-memory cache |
| Read replica | A copy of a database used for reads. It may lag |
| Shard or partition | A split of data across stores so each query touches less |
| Archival | Moving old data to cheaper storage under retention rules |
| Round robin | Give work to each server in turn |
| Least connections | Prefer the server with the fewest active requests |
| Sticky session | Keep sending one user to the same server |
| Health check | A test that a server is fit to receive work |
| Scale up | Make one machine bigger |
| Scale out | Add more machines |
| Elasticity | The ability to grow and shrink |
| Auto-scaling | Adding or removing copies automatically within set limits |
| Capacity planning | Deciding, from peaks and tests, how much resource to hold |
| Queue | A line of work waiting to be processed |
| Back pressure | Slowing producers when consumers are overloaded |
| Circuit breaker | Stop calling a failing dependency for a short time |
| Bulkhead | Separate capacity so one journey cannot consume all workers |
| Retry | Try again. Safe for reads. Dangerous for payments unless idempotent |
| Load shedding | Deliberately dropping less important work to save the core journey |
| Performance budget | An agreed limit on weight and speed of a page or journey |
| HTTP/2 and HTTP/3 | Newer HTTP versions that carry requests more efficiently |
| Connection reuse | Keeping a connection open for later requests |
| Memory leak | Memory that is taken and never released |
| Lock | A control that stops two transactions from corrupting the same data |
| N+1 query | One query for a list plus one extra query per item. A common cause of slowness |

| Deployment | Releasing a version into an environment |
| Domain name | The human-readable site name |
| IP address | The numeric network address |
| DNS propagation | The time for a DNS change to be seen widely |
| A record | DNS that points a name to an IPv4 address |
| CNAME | DNS that makes one name an alias of another |
| Data centre | A secure building for servers, power, cooling, and connectivity |
| Shared hosting | Many customers on one server. Not for a bank channel |
| VPS | Virtual private server. Your own operating system on shared hardware |
| Dedicated server | A whole physical server for one customer |
| Colocation | You own the machine and rent space, power, and network |
| Virtualisation | One physical computer running several virtual computers |
| Virtual machine | A software computer with its own operating system |
| Cloud | Computing, storage, and network consumed as a metered service |
| On-demand self-service | Provisioning capacity without a fresh hardware purchase each time |
| Resource pooling | The provider shares capacity across customers, with separation |
